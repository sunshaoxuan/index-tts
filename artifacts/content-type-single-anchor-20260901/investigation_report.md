# 体裁优先与新闻评论单主播调查报告

## 原始问题

旧流程把作品体裁当作提示词参数。新闻和评论仍进入人物注册、对白分轨、年龄性别推断与人物小传校验，因此稿件中出现或被引用的人物会成为声音角色。

## 实施结论

1. 自动识别先独立判断 `novel`、`story`、`news`、`commentary`，分类阶段不分析人物。
2. 小说和故事体继续使用多人角色分析。
3. 新闻和一般评论进入单主播管线，人物、引语来源和采访对象只作为内容实体。
4. 单主播结果在 AI 输出校验、Worker 角色合并前和导演记忆恢复后三处收敛为唯一 `anchor`。
5. 主播年龄、性别、音色、节奏和表达参数保留在角色资产中供使用者人工设置，稿件人物不会为这些字段提供推断依据。
6. 工程保存 `content_type_analysis`，记录请求体裁、解析体裁、分类方式、依据和单主播标记。

## 真实运行验收

运行环境使用 `indextts25-product-studio:1.1.58-content-type-working` 与 Qwen `qwen3:14b`。受控评论稿包含人名和直接引语，分析结果如下：

| 检查项 | 结果 |
| --- | --- |
| resolved content type | commentary |
| single_anchor | true |
| 角色数 | 1 |
| 角色 | anchor / 主播 / anchor |
| 分句数 | 3 |
| speaker 集合 | anchor |
| 人物校验轮次 | 0 |
| 原文覆盖 | 65 / 65，100% |

页面显示一个主播角色卡，可人工编辑性别、年龄、详细说明、高级声音导演、结构化声音特征、节奏和频率目标。Console warning 与 error 均为 0。

## 边界

主播资产在首次建立时仍使用产品级中性默认基线，例如未指定性别和 35 岁的可编辑初值。该值不来自稿件人物分析。保存人工修改后，资产来源转为 manual。若产品需要“年龄未确认”的空值状态，需要单独扩展角色资产数据结构、频率推荐和音色生成前置校验。
