# 分句导演增量生成与操作记忆调查报告

## 结论

渲染层原有内容哈希缓存已经覆盖实际朗读文字、语言、音色摘要、情绪提示、强度和时长因子，但页面没有片断列表、逐句重生成和严格串接入口。AI 全文分析也会直接覆盖当前角色与分句。

本次把已有缓存提升为可见、可控制的制作流程。最新交付中的片断通过 API 载入，页面使用原文与合成文字双重匹配防止旧序号错配。逐句重生成只强制刷新目标缓存，严格串接拒绝任何缺失片断。服务端保存导演操作快照，AI 分析完成后使用新旧文本序列边界对齐恢复可识别的历史断句、角色和参数。

## 运行态发现与返工

首次页面验收发现最新交付 102 个片断与当前 121 个分句存在版本差异，按序号显示会把旧音频放到错误行。返工后改为原文与合成文字双重一致性匹配，真实页面显示 55 个当前有效片断，第 1 条旧序号片断不再误显示。

最终严格串接测试在当前工程上返回“第 1 条分句缺少可串接的已生成片断，请先单独生成该分句。”，活动任务随后清除，交付目录没有新增。

## 片断失效与完整交付保留

工程保存时由 Node 比较保存前后的分句完整状态和角色配置，定位受影响旧片断。目标缓存键从 `segment-fragments.json` 移除，对应 WAV 从 `segment-cache` 删除。既有 render 目录只追加 `.stale.json`，完整音频、分轨包、导演清单和用户确认删除入口继续保留。

连续编辑时过期记录累积失效键，文字恢复为旧值也不会重新显示已删除片断。最新交付只从具有 `director-manifest.json` 的完整交付中选择，以清单文件时间排序，从而避免过期标记改变目录时间后选中未完成目录。

真实工程第 4 条先完成一次 GPU 单句生成，应用纠音“笹垣”，任务 `3df53959b0a14137822361fa5feef056` 仅推理 1 个片断。随后在页面编辑并保存该条，行内音频从 1 个变为 0，缓存键 `28b2565d28ed13be8fe79da3f8297b77c6db6676d27c983bf72ff5510b57c408` 的 WAV 确认不存在。恢复原合成文字后行内仍为 0 个音频。最新完整音频保留 34,986,518 字节，完整音频、分轨包和清单 HTTP 均返回 200。页面显示过期警告和确认删除弹层，本次验收选择取消，Console warning 与 error 均为 0。
