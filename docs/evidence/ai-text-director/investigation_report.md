# AI 长篇文本导演调查与实现报告

## 目标

输入小说、新闻或故事全文后，使用本机 AI 完成清洗、自然分段、段内分句、人物与旁白识别、角色分轨和态度语气标注，再由 IndexTTS 生成逐句音频、角色轨道和完整音频。

## 已验证架构

1. `production_webui.py` 提供单句创作和 AI 长篇导演两个页签。
2. `text_director.py` 默认按 1400 字符自然边界切分长文，并调用本机 Ollama `qwen3:8b` 的 JSON Schema 输出。单块超时时会继续按自然边界二分。
3. 每条分句包含原文片段、合成文本、角色、语言、态度、八类情绪之一、强度、中文表达节奏和停顿。
4. 程序按顺序重建全文。空白或引号样式变化会恢复为精确原文切片，实质漏文、改写或乱序会触发重试和自动细分，最小块使用无损安全分段。
5. 合并在同一条中的说话归属和引号内台词会再次拆分。`门外忽然传来孩子的喊声：` 可识别出孩子轨道。
6. 用户可编辑角色音色表和逐句导演表，也可使用语义匹配内置音色或 Qwen3-TTS VoiceDesign 生成全新角色音色。
7. 分析、音色设计和完整音频均显示真实阶段和取消入口。分析与音色设计使用独立进程，完整音频在分句边界安全停止。
8. 渲染阶段逐句调用 IndexTTS，再生成完整 WAV、章节 WAV、角色 WAV、CSV、JSON 和 ZIP。
9. `novel_project.py` 为每部小说保存章节、角色、导演表、纠音表、固定音色和过程缓存。
10. 永久音色库使用设计条件、参考文本、模型和固定种子形成稳定签名，相同签名直接复用。旧版角色 WAV 按音频内容迁移为稳定旧版音色 ID。

## 真实运行结果

最终验收使用故事样本，识别旁白、林舟、老板和孩子 4 条轨道，形成 7 条分句，原文覆盖 100%。VoiceDesign 生成 4 条可试听角色参考音频，真实 IndexTTS 使用这些音色生成 16.2 秒完整音频、7 个逐句 WAV 和 4 个角色轨道。浏览器控制台没有错误或警告。

## 发现与修复

1. 直接启动 Python 时，Windows CP932 控制台无法输出部分中文模型日志。正式 Windows 启动脚本设置 `PYTHONUTF8=1`，最终运行使用该入口。
2. 模型有时把中文弯引号改成直引号，导致严格原文覆盖失败。程序现在只对空白和引号等价变化进行精确原文恢复。
3. 模型有时把说话归属和台词合并。程序现在按原文引号边界拆成旁白和人物两条分句。
4. 模型有时遗漏未命名说话者。程序现在从 `传来孩子的喊声` 等归属文字补全人物轨道。
5. 12 列表格曾逐字符换行。角色表和逐句表现在采用明确列宽、固定关键列和横向滚动。
6. Gradio 默认队列提示曾遮盖结果区。所有长任务现在使用自有状态卡，并关闭默认进度覆盖。
7. 生成器取消不会可靠执行 `finally`。取消回调现在显式终止 worker、等待安全线程结束、清理目录、恢复 IndexTTS，并同步更新页面摘要。
8. 16 GB 显存无法稳定同时常驻 IndexTTS、Ollama 和 VoiceDesign。系统按阶段卸载和恢复模型，VoiceDesign 在独立进程退出时释放显存。
9. 旧版 120 秒超时包含 Ollama 冷启动。本次真实日志显示模型加载耗时 99.26 秒，2797 字长文本的单块请求需要 2 分 35 秒。系统现在分析前释放 IndexTTS，让 `qwen3:8b` 以 100% GPU 运行，并将单块上限调整为 300 秒。
10. 覆盖校验失败原本只重试同一块两次。现在覆盖失败也会按自然边界继续细分至约 320 字符，最小块仍失败时转为确定性无损安全分段，并在结果中计数。
11. 真实小说样本暴露了 `narrator` 和“旁白”名称形成重复轨道的问题。角色和分句标准化现在统一使用轨道 ID `narrator` 和显示名“旁白”。
12. `duration_factor` 经代码追踪确认会在声学生成前按目标总长度对语义特征做最近邻插值，无法分别控制声母、韵母和语义停连。长篇导演固定使用中性值，通过角色表达节奏、句内节奏、标点和句后停顿组织表演。
13. 第一次真实合成在 7861、7862、7863 和 Ollama 同时占用 GPU 时明显变慢。保留 7861，关闭已被 7863 替代的旧版 7862，并卸载空闲 Ollama 后，剩余分句恢复正常推进。

## 小说工程真实验收

验收工程包含 2 个章节和 7 条分句。页面新增“内心独白”角色，将心理活动改归该角色，将姓名出现导致的错分句改回旁白。笹垣润三与内心独白共同使用固定音色 `legacy-8f240489d87fa222`。全篇纠音把“重庆银行”统一送入模型为“重 庆 银行”，JSON 同时保留原始文本和实际朗读文本。

真实 IndexTTS 生成 30.16 秒完整 WAV、2 个章节 WAV、7 个分句 WAV和 3 个有内容的角色轨道。第二次生成复用全部 7 个分句缓存。ZIP 有 15 个条目且 CRC 校验通过。浏览器 Console 为 0 error、0 warn，证据见 `09-novel-project.png` 和 `10-novel-project-delivery.png`。

## 长文本真实验收

2797 字故事被切为 2 个自然文本块，识别 4 条角色轨道和 108 条分句，原文覆盖 100%。成功结果包含 4042 个输入 Token 和 12613 个输出 Token，AI 有效请求累计耗时 221.2 秒。浏览器 Console 为 0 error、0 warn，证据见 `07-long-text-success.png`。

覆盖恢复压力样本为 706 字，包含重复段落、编号、引号和零宽特殊字符。初始文本块因覆盖失败依次扩展为 2、3、4 个块，3 个最小块进入无损安全分段。最终形成 3 条角色轨道和 21 条分句，原文覆盖 100%，浏览器 Console 为 0 error、0 warn，证据见 `08-coverage-recovery.png`。

## 限制

1. GPU 测试集有 22 项按项目标记跳过，真实 GPU 推理由最终浏览器音频生成覆盖。
2. 无损安全分段能够保证原文继续处理，其中局部角色和态度标注需要在导演表中复核。
3. 内容体裁差异由提示词约束并有单元测试覆盖。本次浏览器端到端样本使用小说体。
## 2026-08-25 中文枚举导演补充调查

### 结论

1. QwenEmotion 的结构化结果只有喜悦、愤怒、悲伤、恐惧、厌恶、低落、惊喜和平静八维，角色节奏、态度和句内节奏缺少独立数值输出契约。
2. 角色节奏、分句态度、八类情绪和句内节奏改为中文预设。程序保存和合成阶段拒绝未知预设。
3. Qwen3 TTS VoiceDesign 的 `instruct` 原生接受自然语言。页面提供固定中文音色预设和高级自定义音色提示，高级提示优先并原样进入 `instruct`。
4. 旧工程打开时迁移有限控制项。旧音色自然语言条件属于模型原生能力，因此完整保留为高级提示。
5. 长篇合成的 `duration_factor` 继续固定为 `1.0`。枚举节奏展开为语义停连和表达方式提示，没有加入整句波形倍速。

### 真实验收

旧小说工程 4 条角色和 7 条分句成功迁移。浏览器修改旁白高级音色提示和分句预设，保存重开后值保持一致。第一次重新生成得到约 31 秒完整音频、2 个章节和 3 个有内容角色轨；第二次复用 7/7 分句缓存。ZIP 15 个条目通过 CRC 检查，Console 0 error、0 warning。

首次手动重启绕过正式脚本，CP932 控制台无法输出中文路径，第一句保存日志触发编码异常。正式 Windows 启动脚本已经设置 `PYTHONUTF8=1`，按正式入口重启后完整真实生成通过，并新增启动器回归断言。
