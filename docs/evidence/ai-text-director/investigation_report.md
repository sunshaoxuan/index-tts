# React 产品架构与 ORYZO AI 设计验收报告

## 结论

Index Voice Studio 产品页面已经迁移到 React 19、Ant Design 6、Node.js 24 和独立 Python Worker。Gradio 页面、测试、工具和可选依赖已经移除。页面设计已经应用 ORYZO AI 暖暗产品编辑规范，并完成摄影首屏、连续模糊、半透明阅读层和功能导航重构。

## 实现路径

1. `product-studio/src/App.tsx` 提供新建工程、全文与体裁、角色音色、分句导演、全篇纠音和完整交付。
2. `product-studio/server/index.mjs` 提供 REST API、原子保存、枚举校验、旧工程迁移、任务终态和 GPU 单任务互斥。
3. `product_analysis_worker.py` 负责 Ollama 长文本导演。
4. `product_voice_worker.py` 负责永久音色复用和 VoiceDesign。
5. `product_render_worker.py` 负责 IndexTTS 2.5 完整音频、章节、分句、角色轨和 ZIP。
6. `product-studio/src/styles.css` 应用 Walnut Shadow、Warm Cream、Bark Brown、Cork Border 和 Ember 设计令牌。
7. `product-studio/public/hero-voice-workbench.png` 提供原创摄影主视觉，网页文字由 React 独立叠加。
8. `updateHeroDepth()` 将滚动进度映射到背景和首屏内容的模糊、亮度、缩放与透明度。

## 返工记录

浏览器首次打开现有工程时，角色节奏仍显示旧自然语言值。根因是 Node 直接读取旧工程 JSON，有限字段没有经过新枚举迁移。服务层增加确定性迁移后，旧节奏、态度、情绪和句内节奏均返回受支持枚举。迁移和拒绝未知值分别有独立 Node 测试。

工作区首次采用固定顶部导航时，导航深色背景遮住工程顶部。移除背景后，固定层上的导航文字仍与工程文字重叠。最终结构把导航定位限定在首屏内，让导航随首屏离开；工作区从视口 `top: 0` 进入，并在内部保留 102px 顶部安全距离。浏览器测量结果为导航 `bottom: -830px`、工程控制区 `top: 103px`、重叠判定 false。

点击 AI 重新分析全文曾返回 `Bad Request`。服务日志确认 Fastify 错误码为 `FST_ERR_CTP_EMPTY_JSON_BODY`：前端设置了 JSON Content-Type，同时 POST 请求体为空。分析、音色和渲染请求现在统一发送 `{}`，错误信息优先显示服务端 `message`。同一个白夜行工程实际请求返回 202，并完成 3 个文本块。

完全透明工作区在模糊摄影背景上缺少阅读边界。工作区现在带有随内容上滑的 Bark Brown 半透明渐变，桌面透明度为 72% 到 48%，移动端为 78% 到 54%。项目控制条、卡片和表格继续透明。

运行任务原先只禁用顶部任务按钮，全文、角色、分句、纠音和工程选择仍可修改，服务端 PUT 也没有检查活动工程。当前实现将活动任务与 `projectId` 绑定，在 Worker 输入写入前建立锁。前端在任务期间禁用所有工程变更入口，服务端对同一工程 PUT 返回 409。任务完成或失败后释放锁并恢复编辑。

原有进度条嵌在工程控制区内，0% 状态与背景区分不足。当前进度改为固定前景面板，包含任务类型、真实百分比、阶段文字和版本锁定说明。进度轨道高度为 10px，0% 时使用 2% 最小活动填充表达任务正在运行，文字仍显示真实 0%。

角色表音色 ID 原先只是文字标签。当前单元格包含微型播放按钮、音色 ID、14px 命中区的进度轨道、Warm Cream 拖动手柄和时间。服务端把演示音色解析到 `examples`，永久音色解析到 `outputs/voice-library`，并提供 Range 206 响应。

Ant Design 6 下拉菜单采用自定义虚拟滚动，单独的 CSS overscroll 在顶部边界仍会带动页面。当前使用弹层生命周期页面锁和 wheel 边界保护。菜单打开时 `html` 为 `overflow: hidden`，菜单关闭后恢复 `visible`。

角色音色任务运行中刷新页面时，原进度和锁定状态曾消失。根因是 React 只把作业保存在组件内存中，Node 也只保存进程内 `activeJob`。正常刷新不会终止 Node 或 Python Worker，后台仍可能继续运行，页面失去了重新发现任务的入口。当前 Node 持久保存活动作业 ID、类型、工程和 Worker PID，提供 `/api/active-job`；React 首次加载时恢复任务所属工程、相同作业进度与锁定，并继续使用原作业 ID 轮询。服务恢复时检查 Worker PID，失联任务写入 error 并释放锁。

旧角色轨道把 `profile` 和 `voice_hint` 放在拥挤的行内输入中，用户无法区分人物信息与声音特征，也看不到 VoiceDesign 最终参考内容。白夜行旧工程还存在人物小传和高级提示直接等于姓名的记录。当前将 `profile` 明确定义为人物小传，将 `voice_hint` 定义为声音导演建议；名字占位读取时迁移为待补充小传和安全预设。角色表改为摘要，独立编辑窗口展示六类生成依据和最终指令。

实际 VoiceDesign 现在参考作品体裁、角色相关的全局导演上下文、角色类型与名称、人物小传、声音导演、角色节奏和干声约束。全局导演上下文带有角色范围限制，防止“旁白老年男性”等旁白专属要求直接套用到人物。旁白类型与名称相同时只输出一次，避免“旁白旁白”。

## 导演补充串轨与音色性别错配

1. 原老板娘音色 `voice-ea24b5c041442a81` 的最终指令同时包含“中年女性音色”和旁白专属“老年男性音色”，基频中位数约 89.5 Hz。原死者妻子音色约 76.7 Hz。
2. 根因是原实现把完整导演补充复制到每个角色，只附加自然语言提醒“只采用相关要求”。模型仍能直接看到冲突条件。
3. 工程七个永久音色元数据均含原导演补充。旁白使用该条件符合目标；六个非旁白角色属于跨轨污染。
4. 当前流程使用 qwen3:8b 先把导演补充拆成原子片段，再结合完整角色表分配目标。第一次真实返回曾把“旁白缓慢而深沉”错误标为 global，验证器根据明确点名旁白判定无效并要求 AI 重做。
5. 重做结果把“旁白缓慢而深沉”和“老年男性音色”都分配给 narrator。老板娘页面显示 AI 已完成分配，本角色没有收到旁白条件；旁白页面显示两个原子片段、目标旁白和理由。
6. 只读语义测试把“笹垣说话更疲惫”分配给 role_001；把未写姓名的“经营烤乌贼饼摊位的女性声音更温和”依据人物小传分配给老板娘 role_002。
7. 明确性别音色增加硬约束、最多三次生成和基频校验。受污染人物全部切换到无旁白条件的新签名；老板娘新音色 `voice-be9061c4f481bcf8` 约 165.5 Hz，死者妻子 `voice-149d9b9b4c9b4424` 约 155.9 Hz。
8. 七个历史受污染永久音色已保留文件并标记隔离。`find_voice` 和 `list_voices` 会排除隔离元数据，后续工程不能误复用这些音色。
