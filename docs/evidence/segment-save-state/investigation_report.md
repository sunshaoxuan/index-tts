# 分句合成文本保存状态调查

## 结论

用户截图中的第 21 句合成文本 `笹垣衔了根和平牌香烟，擦火柴点zhao2，瞄了一下那份报纸，` 已经存在于当前 `project.json` 和片断索引，刷新后仍能从页面加载。

原页面只在顶部使用按钮禁用状态和“工程已同步”表示保存结果。逐句重生成会先调用统一 `save()`，保存完成后按钮恢复禁用，工作区缺少明确的自动保存说明，容易被理解为修改没有进入工程。`setSegment` 还把 `setDirty(true)` 放在另一个 React 状态更新函数内部，使保存按钮状态依赖嵌套更新的执行时序。

修复将 dirty 登记移到输入事件的明确路径，并在工程控制区和分句导演区同时显示未保存或已保存状态。dirty 存续期间注册浏览器离开保护。逐句重生成继续在启动前保存工程。

## 当前数据证据

第 21 句的 source text 保持 `擦火柴点着`，synthesis text 为 `擦火柴点zhao2`，片断 effective text 同样包含 `点zhao2`。这符合原文保持可审计、合成文本单独编辑的模型。
