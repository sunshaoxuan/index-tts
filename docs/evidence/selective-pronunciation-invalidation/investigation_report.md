# 纠音规则精确片断失效调查

## 结论

旧实现把任意“全篇纠音”变化等同于稿件全量变化，因此新增一个纠音项也会删除全部片断缓存，并将全部完整交付标记为过期。

修复后的服务端对每条旧分句的合成文字分别应用变化前后的纠音表。只有实际朗读文字发生变化的分句进入失效集合。未命中任何分句的纠音变化产生空集合。每份完整交付仅在导演清单包含受影响分句时标记过期，完整音频文件继续保留。

## 行为路径

1. `PUT /api/projects/:id` 比较前后导演快照。
2. `invalidateDirectorArtifacts` 使用与 Python `apply_pronunciations` 一致的启用规则、长词优先和全量替换顺序计算朗读结果。
3. 受影响分句通过角色、语言、原文和合成文字签名定位 manifest 与过程片断索引。
4. 服务端删除受影响缓存文件和索引项。
5. 只有包含受影响片断的交付写入 `.stale.json`。

## 风险边界

旧逻辑已经删除且没有其他副本的片断无法由本次代码修复自动恢复，需要重新生成对应分句。本次修复保护后续保存操作。
