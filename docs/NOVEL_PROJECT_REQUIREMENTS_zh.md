# 小说工程制作需求

## 目标

将 AI 长篇导演从一次性生成流程升级为可长期维护的小说工程。工程应支持整篇小说按章节、段落和分句持续制作，并保证同一人物跨章节使用固定音色。

## 工程数据

每部小说使用独立工程目录，持续保存以下内容：

1. 原始全文、体裁和导演补充。
2. 章节索引、AI 分析结果、角色表和逐句导演表。
3. 角色音色预设或 VoiceDesign 高级自定义提示、稳定音色 ID、参考音频和角色节奏预设。
4. 全篇纠音表。
5. 分句音频过程缓存、每次完整音频、角色分轨、CSV、JSON 和 ZIP。
6. 创建时间、更新时间和数据版本。

## 音色幂等与复用

1. 音色预设展开后的固定提示或高级自定义提示、参考文本、模型和固定种子共同形成音色签名。
2. 相同签名已经存在时直接复用音色库文件。
3. 角色表必须显示音色预设或高级提示、稳定音色 ID、角色节奏预设和是否重新生成。
4. 未标记重新生成且已有固定音色的角色保持原音色。
5. 音色库文件和元数据允许其他小说工程选择使用。
6. 旧版已经生成的角色 WAV 自动迁移到永久音色库。旧版未保存设计条件时必须明确标记条件缺失，音频本身和稳定音色 ID 继续保留。

## 导演表编辑

1. AI 分析得到的角色可以编辑，也可以补充新角色。
2. 分句归属可通过已知角色选择器批量修改，避免手工输入轨道 ID。
3. 角色调整后同步角色名称和类型。
4. 态度、八类情绪和句内节奏使用中文枚举选择，情绪强度与句后停顿继续使用数值。
5. 角色节奏使用中文枚举选择。每个枚举在程序中映射到固定提示，保存和合成阶段拒绝未知值。
6. 角色类型、音色预设、角色节奏、重新生成标记，以及分句角色归属、态度、情绪和句内节奏必须直接使用表格单元格内的原生选择器修改。
7. VoiceDesign 原生支持自然语言音色指令。角色音色提供中文预设和高级自定义提示两个入口，高级提示优先并原样传给模型。
8. 已有工程中的自由文本节奏、态度、英文情绪和句内节奏在打开时迁移为最接近的中文枚举。已有音色自然语言条件完整保留为高级提示。
9. 长篇导演不向使用者暴露整句统一时长倍数。模型内部时长系数保持中性值，句后停顿继续使用毫秒精确控制。
10. 产品页面采用 React 19、Ant Design 6 和 Node.js 24 架构，旧 Gradio 页面、依赖和启动入口全部移除。
11. 产品视觉采用 ORYZO AI 暖暗产品编辑规范，使用暖黑画布、奶油文字、虚线结构、零投影、下划线输入和药丸操作。
12. 页面提供新建工程、全文与体裁、角色与音色、分句导演、全篇纠音和完整交付五个工作区。
13. Windows 产品固定使用专用端口 7864，默认绑定 `0.0.0.0` 供局域网访问，启动时清理该端口的占用进程，不允许在验收过程中漂移端口。Windows 防火墙入站规则只允许 `LocalSubnet` 访问 TCP 7864。
14. 首屏使用全视口摄影产品陈列。进入工作区的滚动过程连续增加背景模糊和压暗，工作区使用随内容上滑的 Bark Brown 半透明阅读层，卡片和表格保持透明。
15. 右上角 Workspace、Voices、Director、Delivery 分别打开对应工作区标签并滚动到工程区域。
16. 顶部导航属于首屏内容，随首屏离开视口。工作区从视口顶部进入，并在内部保留 102px 桌面端或 88px 移动端顶部安全距离，禁止导航与工程文字重叠。
17. AI 分析、音色生成和完整渲染运行时，前景显示独立高对比进度面板，包含任务类型、阶段、百分比和版本锁定说明。
18. 任务开始前保存形成唯一提交版本。任务运行期间，当前工程的全文、角色、分句、纠音和工程选择进入只读状态，服务端拒绝同一工程的 PUT 保存并返回 409。任务终止后恢复编辑。
19. 角色表的每个音色 ID 提供行内微型播放器，支持播放、暂停、拖动进度、当前时间和总时长。演示音色与永久音色库使用同一试听入口。
20. 枚举下拉菜单展开时，滚轮和触摸纵向滚动限制在菜单内部；菜单到顶或到底时禁止滚动链传递到页面或表格。
21. 活动作业状态必须跨浏览器刷新持久化。刷新后自动回到作业所属工程，恢复相同作业 ID、阶段、百分比、等待面板和工程只读锁，并继续轮询到终态。
22. 服务恢复时必须核对持久作业记录中的 Worker PID。Worker 仍存在时继续附着；Worker 已失联时写入明确错误终态并释放工程锁。
23. AI 全文分析必须为每个角色生成基于原文证据的人物小传和声音导演建议。人物小传包含身份、年龄阶段、人物关系、性格、经历和叙事作用；声音导演建议包含年龄感、声线、音高、共鸣、气息、吐字和基础情绪。未知内容必须明确标注，禁止复制姓名或使用空泛占位词。
24. 角色资产区以概览方式显示人物小传状态、声音导演方案、稳定音色样本和编辑入口。人物与音色编辑窗口必须展示作品体裁、全局导演上下文、角色类型、人物小传、声音导演、表达节奏和最终 VoiceDesign 指令预览。
25. 旧工程中人物小传或高级提示等于角色姓名时，读取阶段迁移为明确的待补充小传与可靠音色预设，禁止把姓名作为声音提示继续生成。
26. 完整交付允许重复生成。交付区显示最近一次交付标识，并提供带明确范围说明和二次确认的单次交付删除操作。删除只移除所选交付目录中的完整音频、分轨包、章节、角色轨道和导演清单，工程数据、永久音色和其他交付记录保持不变。
27. 角色音色生成只能复用环境指纹健康的 VoiceDesign daemon。环境指纹必须包含协议版本、实际 Python 解释器、虚拟环境前缀、`qwen_tts` 包来源和模型关键文件状态。旧协议、环境偏移、包不可用或运行时不健康时必须停止旧进程并由专用环境重新启动；最后请求和最后错误必须跨心跳保留。
28. IndexTTS 2.5 合成模型必须由持久 Render Runtime 承载。连续完整渲染或分句重新生成应复用同一已加载模型，单次产品 Worker 结束不得释放驻留模型。切换到 VoiceDesign 时先释放 IndexTTS 模型，切换回音频合成时先释放 VoiceDesign 模型，保证同一时刻只驻留当前任务需要的 GPU 模型。

## 全篇纠音表

1. 每条规则包含原词组合、朗读替换、说明和启用状态。
2. 规则在合成前应用于朗读文本，对同一组合的全部出现位置生效。
3. 原文、导演表原始朗读文本和实际送入模型的纠音后文本均保留在清单中。
4. 较长词组优先替换，空规则和重复原词应被拒绝。
5. 新增、编辑、启用、禁用或删除纠音规则时，服务端必须分别计算每条当前分句在变化前后的实际朗读文字，只让结果发生变化的片断失效。未命中任何当前分句的规则变化不得删除片断缓存，也不得把完整交付标记为过期。

## 长篇与恢复

1. 全文分析继续使用自然边界主动分块、超时细分、覆盖失败细分和无损安全分段。
2. 工程保存章节边界，章节标题和原文位置必须可追踪。
3. 音频生成按分句写入工程过程缓存，相同文本、角色音色和导演参数再次生成时复用缓存。
4. 取消或失败时已完成的分句缓存继续保留，后续生成可以恢复。
5. 完整音频渲染启动前必须释放常驻 VoiceDesign 模型，并在导入 PyTorch CUDA 运行库前写入可见阶段。释放后主机可用内存仍低于安全下限时应明确失败，禁止无限停留在 0% 队列状态。

## 验收条件

1. 工程保存后重新加载，角色、音色、角色节奏预设、逐句导演预设和纠音表保持一致。
2. 相同音色条件两次注册得到相同音色 ID 和同一参考音频。
3. 同一角色跨章节的清单始终引用同一音色 ID。
4. 已知角色选择器可以修改分句归属并同步角色名称。
5. 纠音规则对全文所有命中生效，原始文本保持可审计。
6. 不同角色使用符合人物特点的角色节奏预设，长篇合成保持中性的统一时长系数。
7. 中断后的再次生成能够复用已完成分句缓存。
8. 单元测试、真实页面、浏览器 Console 和截图全部通过。
9. 有限控制项只能保存已知枚举，VoiceDesign 高级自定义音色提示可以完整进入音色生成指令。
10. 摄影首屏、过渡模糊和工作区完全模糊三个滚动状态连续可见，工作区计算背景保持透明。
11. 桌面端和 390 x 844 移动端进入工作区后，顶部导航完全离开视口，工程控制区没有文字重叠，页面没有横向溢出。
12. 角色表和分句表在透明背景上保持可读，原生枚举可展开，宽表格在表格内部提供横向滚动。
13. 任务运行时所有工程编辑控件均处于 disabled 状态，服务端并发保存返回 409；任务终止后保存恢复为 200。
14. 0% 阶段仍能看到前景进度面板和最小活动填充，任务推进时百分比和阶段文字同步更新。
15. 角色音色播放器能够播放和暂停实际 WAV，拖动到中段后当前时间同步变化；音频接口支持 Range 206，缺失音色显示不可用。
16. 下拉菜单内部滚动时页面 `scrollY` 保持不变，菜单到边界后的继续滚动也不移动页面。
17. 运行中任务刷新页面后恢复同一作业 ID、同一工程和只读锁；桌面端与 390 x 844 移动端均显示恢复后的进度面板。
18. 服务恢复测试覆盖存活 Worker 重新附着和失联 Worker 错误终态，终态后 `/api/active-job` 返回不可用并恢复工程保存。
19. 人物与音色编辑窗口能在预设和高级自定义之间切换，修改人物小传、声音导演与重新生成开关时最终指令实时同步。
20. 桌面角色表列不重叠；390 x 844 移动端编辑窗口没有内部或页面横向溢出，窗口内容可以纵向滚动。
21. “姓名加动作，再加低声说或冷冷地问”的对白归属能够识别前方人物姓名，不把“低声”等方式状语当成人名。
22. 人物与音色编辑窗口中的长节奏选项和重新生成设置必须使用独立纵向区域；使用最长真实选项在桌面、窄桌面和 390 x 844 移动端验证两者矩形不相交。
23. 导演补充必须由本地 AI 结合角色 ID、姓名、类型、人物小传和声音提示进行语义路由，输出每个原子片段的目标轨道和理由。角色专属内容未经有效路由时不得进入音色生成指令。
24. AI 路由必须覆盖全部补充片段，不得引用未知角色。明确点名某个轨道的片段不得标记为全局；首次结果校验失败时自动要求 AI 重做，连续两次失败则停止任务。
25. 明确男性或女性的音色生成必须在最终指令开头声明首要声音身份，在结尾再次确认，并执行年龄与目标频率感知的生成后基频检查。候选数量表示通过性别校验后的可选样本数，内部最多尝试请求数量的三倍。零个候选合格时停止注册永久音色。
26. 分句表跨页编辑必须使用分句稳定序号定位，不得使用当前分页内的相对行号。角色变更必须原子同步轨道 ID 与角色名称，保存并刷新后仍保持相同归属。
27. 名称、招牌文字、术语和标题等句内短引用不得仅因引号独立拆句。AI 必须在拆句前结合完整句、相邻句、人物表和说话动作，判断引号属于人物对白、心理活动、句内引用或普通叙述，再生成 segment 边界和角色轨道。短引用保留在完整旁白句中，以正常节奏朗读并由引号形成轻微自然停连。中文双引号、中文单引号、直角引号、双直角引号和 ASCII 双引号使用相同判断规则。
28. 程序规则负责验证 AI 输出的原文覆盖、引号配对、句法连续性和角色合法性，发现明显矛盾时触发 AI 重做或安全修复，不得代替 AI 执行主要语义拆分。
29. AI 已预先拆开的短对白必须从相邻说话动作继承角色。角色正文称呼与角色表名称不同但人物小传包含相同身份词时，应复用已知角色轨道，不得把“老板娘亲切地”等姓名加方式状语创建为新角色。
30. AI 不得输出只包含句号、逗号、引号、省略号或其他纯标点的分句。程序门禁必须把夹在正文中的纯标点吸收到相邻可朗读分句；整篇只有标点时拒绝进入音频生成。
31. 分句导演必须支持勾选连续相邻两条或多条合并，以及选择一条后按原文光标位置拆为两条。跨章节、跨角色或跨语言合并必须拒绝并解释原因；拆分位置两侧必须都有可朗读文字。
32. 合并后使用第一条的角色和导演参数、最后一条的句后停顿，并重新连续编号。拆分后两条继承原角色和导演参数，前半句使用 250 ms 短停顿，后半句保留原停顿，合成文本可继续编辑。
33. 角色资产长列表必须显示持久的当前重点。工程载入时选择第一张卡片，打开人物编辑或以键盘聚焦卡片时更新当前角色。当前卡片必须同时具备摘要提示、卡片背景和定位标记；声音样本播放器保持独立操作，不得触发卡片打开。悬停与键盘焦点应具有独立反馈。
34. 完整交付区必须分别提供完整音频、分轨交付包和导演清单的下载按钮与可见成果物链接。每条链接可直接打开并显示可复制的绝对 URL，使用户能够定位、复制和交付成果物。
35. 分句导演表格的纵向与横向滚动必须限制在表格滚动区域内。鼠标滚轮、触控板或触摸滚动到表格顶部、底部、左侧或右侧边界时，不得继续驱动页面滚动或改变页面位置。
36. 分句导演必须读取最近一次交付中的全部已生成片断，并仅把原文与当前合成文字同时一致的片断加载到对应分句行，逐条提供试听状态和重新生成入口。旧交付序号不得直接绑定已变化的当前分句。重新生成前先保存当前角色、合成文字、导演参数和全篇纠音；只强制生成目标分句，其余匹配片断从工程缓存复用，并形成新的完整交付。
37. 完整交付区必须提供“串接全部已生成片断”。该操作只读取与当前合成文字、纠音结果、音色、情绪、强度和节奏完全匹配的工程缓存；任一片断缺失时停止并显示具体分句序号，不得隐式生成缺失片断。
38. 工程每次保存时必须由服务端比较前后导演状态，记录稿件、角色、断句、角色分配、合成文字、导演参数和纠音变化，并保存可重应用快照。页面提交的历史字段不得直接覆盖服务端历史。
39. AI 重新分析全文后必须基于新旧稿件序列对齐恢复可识别的历史分句边界、角色 ID、角色分配和导演参数。未变化片段保留人工合成文字；发生文字变化的片段回到新原文供复核。稿件相似度过低时保留 AI 新结果并明确记录未应用原因。
40. 分句合并、拆分、文字编辑、角色或导演参数调整后，受影响的已生成片断必须立即从工程索引中失效，并删除对应的片断缓存音频。未受影响片断继续保留。
41. 已合成的完整音频、分轨包和导演清单不得因分句导演调整自动删除。所有受影响的既有交付必须标记为过期，继续允许试听和下载，删除操作只能由用户明确确认后执行。
42. VoiceDesign daemon 只有在解释器、`qwen_tts` 和模型文件健康门禁全部通过后才可接收角色音色任务。模型文件缺失必须在导入 PyTorch 和分配 GPU 前明确失败；发生 `qwen_tts` 导入错误后，下一次任务不得继续复用同一不健康进程。
43. 连续两次分句重新生成必须由同一个 Render Runtime PID 完成。第一次结果标记模型首次加载并保持驻留，第二次结果标记 `model_reused=true`，第二次任务状态不得再次出现“正在加载 IndexTTS 2.5”。角色音色任务开始前必须通过释放协议清空驻留的 IndexTTS 模型。
44. 新增未命中当前分句的纠音项后，全部已生成片断数量、缓存文件和完整交付有效状态必须保持不变。纠音变化只命中部分分句时，只删除对应缓存并过滤对应片断，其他片断继续可试听；仅包含受影响片断的完整交付标记为过期，完整音频文件继续保留。
45. 修改任一合成文本、角色归属、语言或导演参数后，页面必须立即显示“有未保存修改”，顶部保存按钮进入可用状态。保存成功后，分句导演工作区和工程控制区都必须明确显示修改已经保存到工程文件；存在未保存修改时关闭或刷新页面必须触发浏览器离开确认。逐句重新生成会先保存当前工程，自动保存后的按钮可以恢复为禁用状态。
46. 完整交付的 WAV 下载旁必须提供 MP3 下载。用户点击时从当前完整 WAV 实时编码 160 kbps MP3 并流式返回，不预先生成或长期保存 MP3 文件，也不加载 TTS 模型。
47. 产品发布必须使用独立于 IndexTTS 引擎的语义版本。根 `VERSION`、前端包版本、健康接口、页面品牌区、README、CHANGELOG、Git 标签和远程发布版本必须保持一致。
48. 角色区域必须以“一人一卡”的角色资产卡片呈现，不再把尚未进入音频编排的声音样本称为角色轨道。每张卡片集中展示人物形象、姓名、类型、性别、年龄、人物小传、建议频率、目标频率、当前声音样本和编辑入口。
49. 角色卡片必须允许显式选择女性、男性或未指定性别，并填写 5 至 100 岁年龄。系统根据性别与年龄生成可审计的建议基频区间；用户可以在建议区间内用滑块选择目标基频中位数。
50. 性别、年龄、建议频率和目标频率必须持久化到独立 `character_assets`。旧八列角色数据保持可读，缺少角色资产的旧工程在读取和首次保存时自动补齐稳定默认值。
51. 每个角色必须独立持久化十二项结构化声音特征、地域或口音补充、专属试听文本和 VoiceDesign 原生生成参数。结构化声音特征必须明确标识为自然语言指令控制。
52. 生成策略必须提供稳定、平衡、探索和高级自定义。高级设置必须覆盖当前模型支持的主采样、Subtalker 采样、Temperature、Top K、Top P、重复抑制、随机种子和最大生成 Tokens。
53. 每个角色可以请求一至六个合格候选。通过显式性别门禁的候选必须保留声音文件、种子、实测基频和校验状态，用户可以试听并选择其中一个作为当前稳定音色。未通过门禁的内部尝试只保留在本次生成审计记录中，不得注册到永久音色库或显示在候选列表。
54. 角色声音参数变化只使该角色相关片断失效，并把完整交付标记为过期。形象字段和候选列表元数据变化不得使音频片断失效。
55. 年龄变化必须加载年龄段声音特征建议，并使用年龄感知的基频门禁。真实模型验收至少覆盖儿童、成年和老年三组相同文本样本。
56. VoiceDesign 指令必须包含显式性别、年龄、建议基频区间、用户目标基频和与年龄段对应的声带厚度、共鸣位置、亮度及自然质感约束。系统必须按角色配置生成一至六个连续候选，并在通过年龄与性别校验的候选中选择实测中位基频最接近目标的声音。目标值用于自然发声设计和候选选择，不对音频执行电子变调。永久音色元数据必须保存实际候选次数、每个候选的种子、实测频率、目标偏差、校验结果和最终选择。
57. 系统配置必须支持本机保存 OpenAI 兼容 Endpoint、API Key、人物小传模型和图像模型。API Key 只写入被 Git 排除的 `runtime-output/product-settings.json`，读取接口只返回是否已配置，不返回密钥正文。
58. 角色卡片必须分别提供 AI 扩写详细人物小传和生成角色形象。小传扩写只发送角色附近的稿件证据，提示词要求 300 至 600 个中文字符并区分稿件事实与未知信息；形象生成只发送角色名称、性别、年龄、小传和视觉提示。页面在调用前明确展示外部传输边界。
59. 角色形象保存在工程专属 `role-assets` 目录，通过受工程 ID 和安全文件名约束的图像接口读取。形象变化记录为角色资产操作，单独更换形象不得使声音片断或完整音频过期；性别、年龄和目标频率变化必须使该角色声音签名与相关片断失效。
60. 跨角色导演补充污染检查必须限定在当前工程实际引用的稳定音色，并只比较音色元数据中结构化保存的有效导演补充来源。兼容旧音色时只允许检查最终指令中明确标识的“本角色有效导演上下文”区域。人物小传、角色自身声音导演或年龄约束中出现相同词语时不得使音色失效或触发重新生成。
61. AI 人物与图像服务设置必须提供“测试连接并加载模型”。系统通过 OpenAI 兼容 `/v1/models` 使用当前保存或待保存的 Endpoint 与 API Key 读取模型 ID，测试响应只返回 Endpoint、模型 ID 和数量。人物小传模型与角色图像模型必须支持从已发现模型中搜索选择，也允许手工输入兼容服务支持但列表暂未返回的模型名；当前选择不在列表时必须显示明确警告。
62. 本机 Cockpit 与远端兼容节点必须作为相互独立的 Endpoint。设置项必须支持可选 `X-Cockpit-Instance-Id`，并允许人物小传在 Responses API 与 Chat Completions 之间显式选择。模型能力只以当前 Endpoint 的 `/v1/models` 响应为准。回环地址可以使用 HTTP；公网 HTTP 默认禁止发送 Bearer Key，只有用户在风险提示下明确允许后才可调用。
63. 角色形象必须提供至少 10 种以视觉特征描述的漫画风格预设，并提供独立真人写实选项。旧工程和未选择风格的角色默认使用漫画效果；只有明确选择真人写实时才生成真人效果。风格提示不得使用指定作品、画师或商业风格名称。角色可以保存补充视觉要求，形象风格和视觉要求属于视觉字段，不得使声音片断或完整音频过期。
64. 角色卡片列表中的人物形象必须采用适合肖像的较高画幅，并使用偏上方的人脸焦点进行裁切。对竖版、方形和横版生成图都应优先保留完整人脸、头顶和肩部，调整不得改变原始形象文件或角色资产数据。
65. 女性成年角色的声学门禁下限必须同时考虑年龄段下限和用户目标基频减 25 Hz。永久音色元数据必须保存性别校验版本，显式性别缓存只有在当前校验版本通过时允许复用。候选列表必须显示性别校验通过状态，缺少当前校验版本的旧候选必须标记为历史候选待重新校验。
66. 候选声音样本属于角色资产。采用候选只更新角色当前稳定音色和候选选择状态；分句导演只保存稳定角色 ID，不保存候选音色 ID。合成时必须根据分句角色 ID 动态解析角色当前音色，并可直接从永久音色库定位 `voice-*` 或 `legacy-*` 文件。工程 `voice_files` 只作为资产清单和兼容字段，不得成为当前角色音色的唯一解析来源。保存工程时必须把所有存在的角色当前稳定音色回填到资产清单，候选切换不得改写任何分句角色归属。
67. 打开旧工程时必须检查角色当前稳定音色与 `voice_files` 的一致性，存在可定位但未登记的永久音色时通过临时文件和原子重命名写回 `project.json`，不得等待用户再次编辑或保存。持久 Render Runtime 必须记录合成源码指纹；指纹缺失或与当前代码不同的进程不得复用，下一次任务前必须安全停止并重新启动。
