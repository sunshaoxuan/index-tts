# Qwen3 14B 与空分句调查报告

## 直接结论

2026 年 8 月 28 日 12 时前后的两次白夜行02全文分析实际都使用 `qwen3:8b`。两次 AI 输出均连续未通过原文完整覆盖校验，随后安全兜底把句末右引号拆成独立文本块，并因朗读文本为空而失败。工程采用完整分析成功后原子写入，因此分句表保持 0 条。

当前 7864 全局设置已经切换为 `qwen3:14b`，模型发现接口确认本地 Ollama 已安装并提供该模型。代码默认值、设置页面初始值和架构文档也同步改为 14B。

## 修复

`split_document` 在自然边界拆块时把成对句末引号和尾随空白纳入前一文本块，避免产生单独且不可朗读的标点块。安全兜底仍执行原文覆盖、字段和可朗读性校验。

提交 `cebaf42` 部署后，真实 `qwen3:14b` 任务 `09838d0fc3ed404e93e392817d9cb4fe` 完成了 17 个自适应文本块，随后在 `document_to_tables` 阶段以“没有可用于角色分配的演示音色”终止。分析 worker 只扫描 `/app/examples/voice_*.wav`，干净提交构建不包含被 Git 忽略的本地示例 WAV，因此没有消费工程已经导入的 22 个正式音色。

角色分配音色来源已改为工程当前音色、角色候选音色、工程音色文件、正式音色库和可选示例音色的有序合集。该修复允许干净镜像直接使用工程与正式音色库资产，不再依赖构建机的忽略文件。

关联工程的首次新文章分析还必须执行角色资产并集。合并规则以角色类型和去空白、大小写归一化后的名称为匹配键；重叠角色沿用已有稳定 ID 与完整角色行，新角色在冲突时分配新的 `role_NNN`，未在本篇出现的已有角色继续保留。AI 文档和分句中的说话人 ID 同步改写为最终 ID，并把复用、新增和保留数量写入 `document.linked_role_merge`。

## 运行影响说明

本轮纠音 UI 验收服务曾与 7864 共用 `runtime-output`。7866 启动时读取了容器任务 PID，并在 Windows 进程域中判断为失联，删除了第二轮任务的 active job 登记。容器内 worker 继续运行并最终进入同一错误终态。这个干扰会影响刷新页面后的进度恢复，不改变两轮任务的 8B 输入、AI 覆盖失败或安全兜底错误结论。7866 已停止，后续验收必须使用独立运行目录。
