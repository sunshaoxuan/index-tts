# 单分句锁定与三候选补生成调查报告

## 调查范围

本次调查覆盖生成单个分句时的界面锁定范围、高级三版候选的补生成规则、任务进度、过程审计、完成后的工程状态合并和生产页面行为。

## 原因

单分句任务已经保存目标序号，但分句表的文本、导演参数和选择控件仍统一读取工程级 `jobRunning`，因此一个分句运行时整张表都无法编辑。任务完成时前端还会采用服务端任务开始时的工程快照，存在覆盖运行期间其他行编辑的风险。

高级三版原流程把尝试预算固定为九次。旧生产任务 `5a4cb985375c4ce187ebd97eb7e3a0dc` 与 `6de5e56dce0e419fb83c882ee791af80` 都实际尝试九次，最终只有两份候选通过参考音色门禁。页面只显示终态，缺少尝试次数和累计通过数量，使用者无法判断系统是否执行过补生成。

## 修改

前端把单分句状态扩展为保存、提交和运行三个阶段，并在全过程保留目标序号。分句编辑器根据工程级任务和目标行身份计算锁定状态。目标行锁定，其他行继续允许编辑；音频生成入口保持互斥。单分句完成时只刷新最新音频结果与运行状态，保留本地工程对象和未保存修改。

高级三版的有限预算调整为三十次。每次候选执行基础音频、参考音色和适用重音门禁，单次异常也进入失败统计。系统持续尝试到三份候选全部通过，或三十次预算用完。任务状态写入“第 N/30 次，已通过 X/3”，工程过程目录写入逐次审计。预算耗尽错误包含实际尝试数、通过数量和分类失败次数。

## 生产实测

工程《成都粉子》第 27 条以高级三版方式生成。运行态中第 27 行的合成文本与全部导演参数被锁定，第 28 行的同类控件保持可编辑，其他生成按钮保持互斥。进度从 `3/30，0/3` 继续推进到 `14/30，2/3`。

任务在第十五次尝试后完成。三份候选的参考音色相似度为 `0.837047`、`0.827484` 和 `0.824573`，均通过 `0.820` 门禁。十二次失败全部归类为 `speaker_identity`。页面重新读取后显示三份可播放候选，第一份继续保持当前采用，系统没有执行自动采用。

浏览器控制台日志为零。生产容器使用镜像 `indextts25-product-studio:1.1.89-7f419d9`，任务完成后容器保持 healthy。

## 结论

单分句锁定范围符合目标行粒度。高级三版具备有限预算内的持续补生成、实时反馈和逐次审计。真实样本证明被拒绝候选会继续补充，最终交付三份全部通过适用门禁的候选。
