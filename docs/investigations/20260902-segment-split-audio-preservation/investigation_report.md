# 分句拆分后生成音频清空下一句调查

## 用户初衷

拆分分句后，生成其中任意一条分句音频只更新目标分句，后续分句已经生成的音频必须继续保留。

## 已验证根因

拆分会重排后续分句序号。过程片断索引仍保留旧下一句的历史序号，新拆分句生成后会出现两个不同文本片断暂时拥有同一序号。

`GET /api/projects/:id/latest-render` 在执行文本身份对齐以前，使用按序号索引的 `Map` 对过程片断做提前去重。该步骤会丢弃其中一个不同文本片断，使后续的一对一文本匹配失去候选。

## 修复契约

过程片断读取阶段保留全部不同缓存片断。最终返回仍由 `reconcileFragmentsToProject` 按当前工程的原文与合成文本一对一匹配，并将返回序号改写为当前工程序号。

接口级回归必须覆盖以下顺序：下一句已有过程音频，拆分前一句，生成拆分出的新句，两条片断历史序号相同，接口仍同时返回新句和后移下一句的音频。

## 运行验收结论

部署后建立同历史序号冲突的临时工程。服务端将两个片断分别对齐为当前第 15、16 句，真实页面同时显示两个可播放播放器。后一句媒体加载完成并成功推进播放进度，Console 无警告或错误。临时工程在验收后通过产品删除接口清理。
