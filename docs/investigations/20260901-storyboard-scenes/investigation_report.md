# 视频分镜场景增强调查与实现报告

## 目标

将 Product Studio 的场景分析升级为视频分镜工作流。内容主题变化时建立新场景；小说中的地点、室内外、人物方位、观察方向或叙事焦点变化时也建立新场景。AI 为每个场景撰写可用于关键帧生成的场景小记。已有完整音频时显示开始时间、结束时间和时长，尚无音频时隐藏音频时间。关键帧提供风格选择、单张重新生成和全量重新生成。

## 实现结果

1. AI 场景结构新增分镜标题、内容主题、空间方位、场景小记、切换依据和起止分句序号。
2. AI 提示明确内容主题、地点、室内外、人物方位、观察方向和叙事焦点的场景边界规则，并要求生成 80 至 220 个中文字符的场景小记。
3. 分析结果根据分句的 `scene_id` 归集起止分句，并清理没有实际分句引用的场景。
4. `buildSceneAudioRanges()` 根据完整交付 captions 中的真实 WAV 时长和 `pauseAfterMs` 计算场景音频开始、结束和时长。没有 captions 时返回空结果，页面不显示音频时间。
5. 服务端提供九种关键帧风格、单场景生成接口、全量生成接口和工程专属 `scene-assets` 文件服务。生成尺寸为 `1536x1024`。
6. 视频分镜页使用 16 比 9 关键帧卡片，显示主题、地点、空间方位、故事内时间、叙事视角、参与人物、基调、AI 场景小记、切换依据、原文证据和起止分句。
7. 页面提供全量风格选择、单场景风格选择、单张生成与重新生成、全量生成与重新生成。
8. `README.md`、`CHANGELOG.md` 和 `docs/NOVEL_PROJECT_REQUIREMENTS_zh.md` 已同步本次需求与使用说明。
9. 同批交付纳入 IndexTTS 与 VoiceDesign 独立模型命名卷和模型运行遥测，保留最新 `master` 的 Python 依赖与正式输出挂载。

## 事实与限制

1. 生产环境的现有工程均为旧场景数据格式，当前选择的“白夜行01”没有视频分镜。生产页面验收覆盖真实部署、风格选择、场景边界说明、空状态、响应式布局和 Console。
2. 含场景数据的完整卡片验收使用隔离 fixture，覆盖 AI 场景小记、起止分句、音频时间、单张按钮和全量按钮。
3. 关键帧生成会把当前场景小记及参与人物小传发送到用户配置的兼容图像服务。实际图像质量和响应时间取决于该服务。
4. `tests/test_v1.py` 与 `tests/test_v2.py` 需要对应代际 checkpoint。当前 checkpoint 配置与这两组推理 fixture 不匹配，因此本次应用回归明确排除这两个文件。
5. 本地 `master` 被并行开发工作树占用且存在未完成修改，本次交付使用干净的 detached 交付工作树更新远端 `fork/master`，避免覆盖并行工作。
