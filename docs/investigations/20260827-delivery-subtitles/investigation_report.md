# 完整播放滚动字幕调查与实现报告

## 直接结论

完整音频由交付清单中的分句 WAV 按顺序串接，并在每条 WAV 后写入 `pause_after_ms` 停顿。最新交付接口原先已经返回角色、原文和分句音频地址，缺少每条分句的真实时长，因此页面只能播放完整 WAV，无法建立精确字幕时间轴。

本次在最新交付接口增加专用 `captions` 清单。服务端读取每个真实 WAV 的 RIFF 数据块与字节率，返回角色、原文、时长和句后停顿。前端按清单顺序累计时间，播放与进度输入变化时定位当前字幕，并将高亮项滚动到字幕容器可视区域。

## 行为链路

1. `director-manifest.json` 保存分句顺序、角色、原文、片段路径和句后停顿。
2. `GET /api/projects/:id/latest-render` 读取清单和每个分句 WAV 头，生成 `captions`。
3. `buildCaptionTimeline` 累计片段时长与停顿，生成每条字幕的开始与结束时间。
4. `StudioAudio` 的 `timeupdate` 和进度条 `input` 更新当前时间。
5. `activeCaptionIndex` 选中当前字幕，React effect 将高亮项滚动到容器中央。

## 已验证事实

真实工程最新交付包含 133 条字幕。累计字幕时间为 816.9663945578237 秒，完整 WAV 为 816.965941043084 秒，差值为 0.00045351473977461865 秒。接口处理耗时约 43 毫秒。

浏览器开头显示 1 / 133。播放约 7 秒后显示 2 / 133。定位到 408.4 秒时显示 62 / 133，字幕容器 `scrollTop` 为 2998。定位到 816 秒时显示 133 / 133 和最后一句。浏览器 Console warning 与 error 均为 0。
