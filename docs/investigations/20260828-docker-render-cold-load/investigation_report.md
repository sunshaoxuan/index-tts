# Docker 完整渲染首次冷加载调查

## 调查问题

完整音频渲染在 Docker 中长时间停留于“正在加载 IndexTTS 2.5”，GPU 和显存早期没有明显变化。需要判断 Docker 是否整体比 Windows 本机慢，并修复可确认的部署瓶颈。

## 结论

当前部署的明显慢点集中在首次冷加载。作业 `02377f22cc504c8b851dab14172f654f` 首次装载约 11.66 GB IndexTTS 模型，用时约 4 分 50 秒。模型驻留后，作业 `58532eb0d1c242d3b1465108d5ba4243` 与 `f34fdb55da7f42e5b01bc3eb0961adcd` 分别约 5 秒和 6 秒完成。

首次加载时，模型通过 Windows 绑定目录 `D:\workspace\IndexTTS-2.5\checkpoints` 进入 Linux 容器。模型会先经历宿主文件系统读取和 CPU 内存初始化，GPU 显存增长位于后段。当前实测将相同数据从绑定目录迁入 Docker 命名卷时，约 18 分钟完成约 8.05 GB，复制读取进程进入磁盘等待，证明该跨文件系统路径是当前主要瓶颈。

本轮修复把 IndexTTS 与 VoiceDesign 模型分别放入 Docker 命名卷。应用镜像继续只包含运行环境和代码。完整渲染页面增加 Render Runtime 的进程存活、加载阶段、内存、累计读取字节和模型总字节遥测。

## 事实与边界

| 结论 | 证据 | 置信度 | 限制 |
|---|---|---|---|
| 首次冷加载明显慢 | 作业开始于 22:41:17.960Z，完成于 22:46:07.824Z | 高 | 仅代表当前机器和旧绑定目录部署 |
| 驻留后推理速度正常 | 两个后续作业约 5 秒和 6 秒，结果显示复用驻留模型 | 高 | 分句内容和长度可能影响绝对耗时 |
| Windows 绑定目录是主要瓶颈 | 11.66 GB 模型卷迁移约 18 分钟时完成 8.05 GB，读取进程为磁盘等待状态 | 高 | 尚需新命名卷冷启动基准量化改善幅度 |
| Docker GPU 推理整体变慢 | `evidence_missing` | 低 | 当前证据只支持冷加载路径变慢，热加载没有同等降速 |

## 风险与后续验收

1. 命名卷复制完成前不能切换正式容器。

4. 必须执行新容器真实冷启动与热启动基准。
5. 必须完成页面、Console 和截图验收。
