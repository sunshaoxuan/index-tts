# 长时间操作统一取消调查报告

## 调查目标

确认 Product Studio 中可能长时间等待的音频、图片、AI 和工程读取入口，建立从可见按钮到服务端、Worker、Runtime 和上游 HTTP 请求的完整取消链路。

## 范围

| 类别 | 操作 | 取消机制 |
|---|---|---|
| 后台音频 | 单分句生成、完整音频生成、严格串接 | `DELETE /api/jobs/:id` 取消队列或运行任务 |
| 后台 AI | 全文分析、AI 分镜重建、角色音色 | `DELETE /api/jobs/:id` 终止 Worker |
| 图片 | 单张关键帧、全量关键帧、角色形象 | 浏览器 `AbortController` 传递到 Node 上游 `fetch` |
| 同步 AI | 人物小传扩写、兼容 Endpoint 测试、全文分析服务测试 | 浏览器 `AbortController` 传递到 Node 上游 `fetch` |
| 工程读取 | 工程切换 | 中止工程与最近交付请求，保留当前工程 |

## 行为追踪

1. React 为后台任务显示统一进度浮层和“取消当前任务”。单张与全量图片、人物扩写、角色形象、两类服务测试和工程切换使用各自的取消按钮。
2. 后台任务调用 `DELETE /api/jobs/:id`。等待任务从持久队列移除并进入 `cancelled`。运行任务先进入 `cancelling`，随后终止当前 Worker 并写入 `cancelled`。
3. 音频和音色任务在终止 Runtime 前读取 `state.json` 与 `.processing` 信封。请求 ID、状态路径和当前任务不一致时，不终止该 Runtime。
4. 同步 AI 和图片请求把浏览器中止信号传给 Node。Node 监听客户端请求断开并把 `AbortSignal` 传入兼容服务或 Ollama 的上游请求。
5. 全量关键帧先完成全体预检，再逐张生成。每张成功后立即写入 React 工程草稿。取消当前请求后不再启动下一张，先前完成图片继续保留。

## 结论

所有已盘点的长时间操作都有可见取消入口。后台任务、同步 AI、图片和工程读取分别采用适合其生命周期的取消方式。音频 Runtime 取消具备归属门禁，降低终止其他任务的风险。浏览器隔离验收在全量关键帧 `1 / 2` 时取消，最终只保留第一张，第二个上游请求被中止。

## 限制

* 浏览器验收使用隔离工程、模拟上游服务和模拟 Worker，未消耗真实模型额度。
* Runtime PID 归属终止由真实服务代码和单元测试验证，本轮未终止生产 GPU Runtime。
* 本报告记录实现与隔离运行验收，未执行产品 Docker 发布。
