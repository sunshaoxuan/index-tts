# IndexTTS 分句导演质量调查报告

## 1. 调查范围

本报告分析测试工程“白夜行01”的自动分句、说话人归属、人物合并、情绪、态度、句内节奏、强度、停顿和场景理解能力。

本轮只做调查、评估和改进建议。生产提示词、模型路由、工程数据均未修改。小说正文也未发送到外部 Endpoint。

测试工程路径：`outputs/novel-projects/20260825-104455-白夜行01-869866`

当前人工版本：133 条分句，8 个角色，143 次导演保存记录。

## 2. 结论摘要

当前质量差距由三类原因共同构成。

1. 模型理解问题：角色指代、别名合并、对白归属、态度与节奏判断仍有较多错误。
2. 提示词任务过载：单次请求同时承担清洗、分句、角色发现、角色小传和全部导演参数，输出预算及注意力被分散。
3. 数据契约与后处理问题：模型输出的态度会在预设转换时大量回退，AI 节奏枚举与产品控件不一致，场景信息没有可持久化结构，分块处理也削弱全文连续性。

因此，直接更换模型无法完整消除当前问题。最合适的顺序是先统一数据契约并拆分分析阶段，再用固定金标准比较 Qwen 与 GPT 模型。

## 5. 实现层原因

### 5.1 态度输出发生预设映射损失

提示词要求模型输出具体态度，Schema 允许自由字符串。最后一次 Qwen 原始值包含中性、平静、叙述与说话归属、叙述、客观陈述、担忧、陈述、疑问、好奇、慌张、思考和礼貌。

`migrate_attitude_preset()` 只识别有限关键词。未命中的值统一回退到“中性叙述”。最后一次 Qwen 的 121 条结果进入产品表格后全部成为“中性叙述”。这部分损失发生在模型输出之后。

代码位置：`text_director.py:1308`

### 5.2 AI 节奏枚举与产品控件不一致

AI Schema 只允许 `slow`、`medium`、`fast`。产品表格实际提供自然、舒缓、强调、轻快、低声、克制和紧凑。模型没有直接选择“强调、低声、克制、轻快”等产品级预设的能力。

代码位置：`text_director.py:657`、`text_director.py:1164`、`text_director.py:1294`

### 5.3 场景没有显式数据结构

当前 segment 保存说话人、语言、原文、合成文字、态度、情绪、强度、节奏和停顿。Schema 与工程数据均未保存场景 ID、地点、时间、参与者、叙事视角、对话对象、场景基调、转换边界、置信度和证据片段。

当前系统无法稳定比较、人工修订和复用场景判断。提示词可以改善临时推理质量，场景导演仍需要对应的数据模型与编辑入口。

### 5.4 分块处理削弱全文连续性

当前最大文本块为 1400 字符。最后一次分析拆成 7 个块，每块只获得已有角色表和上一块末尾约 400 字符。同名与别名只按精确名称合并。

“松野教授”与“松野秀臣”，“胖女人”与“中年妇人”及“老板娘”，“其中一个”与“对方”等表达需要更长上下文和稳定别名注册表。

代码位置：`text_director.py:236`、`text_director.py:450`、`text_director.py:530`

### 5.5 说话人后处理缺少歧义表达

`_match_context_speaker()` 使用上下文词匹配角色姓名或小传。多个角色可能共享“年轻刑警”“中年”“教授”等描述。当前结构没有候选角色、置信度和证据字段，也没有 `unknown` 或 `uncertain` 状态。

系统在证据不足时仍需给出有效 `speaker_id`，容易形成格式正确、语义错误的角色归属。

代码位置：`text_director.py:951`、`text_director.py:990`

### 5.6 单次请求的任务密度过高

当前请求同时处理原文清洗、分句、引号分类、人物发现、角色小传、声音导演、态度、情绪、强度、节奏、停顿、语言、角色 ID 和原文完整覆盖。每个角色小传还要求 300 至 600 个中文字符。

角色小传和全部导演参数占用输出预算，也会分散对白归属和边界判断所需的注意力。

## 6. 提示词改进建议

提示词改进应配合 Schema 改造执行。推荐拆成四个明确阶段。

### 6.1 全文角色与场景注册

输入全文的确定性段落 ID 和字符偏移。输出角色注册表、规范名称、别名、描述称谓、首次证据、场景边界、地点、时间、参与者、叙事视角与场景基调。

提示词要求每个新角色必须引用原文证据。证据不足时输出待确认实体，不强制创建正式角色。

### 6.2 对话归属

输入固定原文单元、场景注册表和角色注册表。输出 `speaker_id`、候选列表、置信度、判断依据和证据偏移。要求区分对白内容、对白后的叙述动作和引用文本。

对低置信度归属保留待确认状态，并在 UI 中集中呈现。

### 6.3 分句边界

输入固定原文单元和已确定的说话人。模型只决定相邻单元的合并或拆分。提示词加入可听性约束：单句目标时长、最大字符数、标点强度、语义闭合、同一说话人连续性和换气位置。

原文字符偏移保持不可变，模型只返回边界决策，避免重写原文。

### 6.4 声音导演参数

Schema 直接使用产品预设 ID。每个态度、情绪和节奏枚举都提供定义、正例、易混淆反例和优先级。情绪表示人物内在状态，态度表示对听者或事件的姿态，节奏表示句内推进方式。三者分别判断。

提示词要求引用触发词、上下文关系或场景基调作为简短证据。相邻句出现异常跳变时进行一次一致性复核。

### 6.5 建议加入的提示词规则

1. 人物名称必须从角色注册表选择，新增人物需提供原文证据和规范名称。
2. 描述性短语含有副词或动作词时，不得直接作为人物名称。
3. 姓名、职称、外貌称谓和关系称谓需要进入同一角色的别名集合。
4. 证据不足时输出待确认状态，并给出最多三个候选。
5. 每个分句返回原文起止偏移，输出文本必须与原文切片完全一致。
6. 对白内容与“某人说”“某人问”等叙述成分分开归属。
7. 导演参数只使用产品枚举 ID，不输出自由文本替代值。
8. 对同一场景内连续句的说话人、情绪和节奏执行一致性检查。
9. 场景转换必须引用时间、地点、人物集合或叙事视角变化证据。
10. 角色小传移到独立阶段，不占用分句和对白归属请求的输出预算。

## 7. 推荐的数据与分析架构

1. 确定性原文锚点层：为段落、标点单元、引号和字符偏移建立不可变 ID。
2. 全文角色与场景层：建立角色注册表、别名、场景边界和参与关系。
3. 对话归属层：在固定原文单元上输出候选、置信度和证据。
4. 分句导演层：只决定合并边界和产品级导演参数。
5. 产品枚举层：Schema 直接使用产品预设 ID，取消自由字符串的二次猜测映射。
6. 验证层：增加场景连续性、别名冲突、低置信度、异常情绪跳变和超长分句检查。
7. 评测层：将当前版本经过人工确认后冻结为金标准，并保存字段级评测结果。

## 8. 模型评估与生产建议

### 8.1 当前模型状态

本地 Ollama 可用，已安装 `qwen3:8b`、`qwen3:14b` 和 `qwen3-embedding:8b`。当前生产分析模型为 `qwen3:8b`。

已连接的兼容 Endpoint 可发现 `gpt-5.6-luna`、`gpt-5.6-terra`、`gpt-5.6-sol`、`gpt-5.6`、`gpt-5.5` 和 `gpt-5.4` 等模型。本轮只读取模型列表，没有发送小说正文。

根据 OpenAI 当前官方文档，GPT 5.6 Luna 面向成本敏感和高吞吐场景，Terra 用于能力与成本平衡，Sol 用于复杂专业任务。Luna 支持 Chat Completions、Responses API 和 Structured Outputs。

官方资料：

1. [GPT 5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
2. [GPT 5.6 模型指南](https://developers.openai.com/api/docs/guides/latest-model)
3. [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

### 8.2 推荐盲测矩阵

第一组使用统一的新 Schema 和分阶段提示词，比较：

1. `qwen3:8b`
2. `qwen3:14b`
3. `gpt-5.6-luna`
4. `gpt-5.6-terra`
5. 预算允许时加入 `gpt-5.6-sol`，作为质量上限参考

每个配置固定原文、提示词、Schema 和采样参数，至少重复三次。评测角色归属准确率、边界精确率与召回率、别名合并准确率、情绪宏平均 F1、态度一致率、节奏一致率、场景边界准确率、低置信度校准、延迟和成本。

### 8.3 生产路由建议

当前证据支持继续保留 Qwen 作为本地基线，并优先评测 `qwen3:14b`。GPT 5.6 Terra 适合作为主要外部质量候选，Luna 适合作为高吞吐成本基线，Sol 适合作为复杂样本的质量上限。

生产模型选择应基于盲测结果。若本地 14B 达到质量门槛，可保留隐私和离线优势。若外部模型在角色归属、别名和场景指标上有稳定显著提升，可讨论全量调用或低置信度升级路由。

## 9. Endpoint 风险

当前兼容 Endpoint 使用公网 HTTP，Bearer 凭据和请求内容缺少 TLS 传输保护。调查过程中工具输出曾显示本地 API Key，本报告没有记录该值。

在外部模型测试前应轮换该凭据，并将 Endpoint 改为 HTTPS，或由使用者明确接受传输风险。还需要限定发送的测试原文范围、模型、用途、保留策略和日志策略。

## 11. 建议执行顺序

1. 由人工确认当前 133 条版本可作为金标准候选，并补验强度、停顿和场景边界。
2. 统一态度和节奏的产品枚举，增加场景、候选、置信度和证据结构。
3. 将全文角色场景、对白归属、分句边界和声音导演拆成独立阶段。
4. 建立自动评分器和三次重复盲测流程。
5. 先比较 Qwen 8B 与 14B，再在完成凭据轮换和 HTTPS 保护后比较 Luna、Terra 和 Sol。
6. 根据质量、成本、延迟和隐私门槛讨论生产路由。

最合适的下一步是进入“金标准确认与盲测设计”，此步骤不需要立即切换生产模型。
