# IVS 项目关联与角色音色导入调查及实现报告

## 需求

新建声音工程时可关联一个或多个已有工程，并导入来源工程的角色、每个角色的全部音色和全篇纠音规则。

## 已验证实现

1. 新建工程窗口提供多选来源工程，选项显示来源工程角色数。
2. 创建接口接收 `source_project_ids`，导入角色表、结构化角色资产、当前音色和全部候选音色。
3. 多来源工程出现相同角色 ID 时，为新工程分配不冲突的稳定目标 ID。
4. 新工程保存 `linked_projects` 回执，记录来源工程、角色 ID 映射、可用音色和缺失音色。
5. 导入是创建时快照，创建完成后各工程独立维护。
6. 仅规范化来源快照中的角色投影，避免处理大型导演历史。
7. 多来源纠音按选择顺序合并。完全重复规则去重，同原词内容冲突时保留首个来源规则，并在 `linked_projects` 中保存重复与冲突回执。
8. 合并后的纠音规则同时写入当前工程与 `director_memory.pronunciations`。

## 运行证据

真实来源工程 `20260825-104455-白夜行01-869866` 的 `project.json` 为 16,094,240 字节，包含 8 个角色。返工后创建关联工程耗时 116 ms，导入 8 个角色和 22 个音色引用；22 个音色文件全部可用，缺失数为 0。

内置浏览器显示新建窗口包含“关联已有工程并导入角色、音色与纠音”多选项。通过页面创建后显示成功提示“已导入 8 个角色、22 个可用音色和 4 条纠音规则”，工作区显示“角色资产 8”和“全篇纠音 4”，四条来源规则可编辑，Console 错误和警告列表为空。

最终复核时，7864 Docker 容器为 healthy。其生产 bundle 包含本功能字段文案，项目列表接口返回 `roleCount`。

最终截图成功保存到 `artifacts/ivs-project-link-import/pronunciation-import-browser-final.png`。

## 限制

关联记录用于审计导入来源，不提供来源工程后续变更的自动同步。来源项目内已经缺失的音色文件会保留候选 ID，并写入 `missing_voice_ids`。
