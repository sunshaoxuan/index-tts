# 分句候选采用后主播放器未刷新调查报告

## 结论

候选采用接口会替换稳定片断文件，并更新候选选择记录。最近交付接口继续返回相同的稳定片断 URL。前端 `FragmentAudioPlayer` 只在 `src` 字符串变化时重置，因此媒体元素保留旧时长、旧缓冲和旧播放状态。

修复后，主播放器 URL 将当前采用候选 ID 编码为 `selected_candidate` 查询参数。选择变化会产生新的媒体身份，触发媒体元素重建和加载状态重置。候选采用请求期间同步锁定重复提交。

播放器改为统一的自定义控件。主播放器使用蓝青色基础表面，候选播放器使用紫色基础表面。加载与缓冲为琥珀色，就绪为青绿色，播放中为亮蓝色，暂停为紫色，完成为绿色，失败为红色，同时保留状态文字与按钮语义。

## 已验证事实

| 结论 | 证据 | 置信度 | 限制 |
|---|---|---|---|
| 主播放器未刷新的根因是稳定 URL 未改变 | 采用前后 `fragment.audio` 路径相同，旧实现以 `src` 为重置依赖 | 高 | 无 |
| 当前采用候选可作为媒体身份 | 浏览器实测 URL 从候选 3 ID 切换到候选 1 ID | 高 | 无 |
| 新媒体身份触发重新加载 | 切换后立即出现 `loading`、`0:00 / 0:00`，随后变为 `ready`、`0:00 / 0:03` | 高 | 无 |
| 状态配色和文字同步变化 | 浏览器 computed style、DOM 状态文字与截图 | 高 | 播放完成态由代码和测试覆盖，未等待完整三秒单独截图 |
| 原采用项已恢复 | 验收结束后候选 3 再次显示“当前采用”，URL 恢复原候选 ID | 高 | 无 |

## 风险

生产构建仍包含既有的大 chunk 警告。该警告未影响本次功能、构建或运行健康状态。
