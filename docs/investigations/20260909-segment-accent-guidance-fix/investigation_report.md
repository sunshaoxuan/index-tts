# 分句口音指令失败调查

## 问题

工程“成都粉子02”第 3 条在情绪细化描述中填写“成都口音”后，标准单版生成以 `candidate_exception` 失败。

## 证据与结论

生产作业 `35707ca021794d7b908d463e20e73e36`、`10c2fcd0f28342a3ae5695d9790414b5` 和 `3f0768da2a5d4da39faa769f1771328f` 均在一次尝试后失败。Render Runtime 日志连续记录 `starting inference`，未形成 `detected emotion vectors`，异常发生在 QwenEmotion 分类阶段。

第 3 条的第 14 列为“成都口音”，角色旁白的 `voice_traits.accent` 为空。渲染器会把第 14 列拼入 `emo_text`；QwenEmotion 只输出高兴、愤怒、悲伤、恐惧、反感、低落、惊讶和平静八维向量。`infer_v2_5.py` 原实现直接对返回值执行数值范围比较，字符串或结构化说明会触发类型异常。

地域口音需要在角色声音生成阶段进入 Qwen3 TTS VoiceDesign，并成为角色稳定参考音色的一部分。当前角色弹窗虽已有数据输入，但位于十二个滑块之后，角色列表和指令摘要均未显示，入口可发现性不足。

## 修复范围

- 提升角色地域或口音控件，补充角色列表和最终指令摘要。
- 前端在分句提交前识别口音误填并打开对应角色卡片，后端执行同一校验。
- 两套 IndexTTS QwenEmotion 解析字符串数值，对异常值按零处理并在全零时回落到平静。
- 标准单版与高级三版均保存候选审计，错误显示中文分类和首个原始异常。

## 最终验收结论

口音已经从分句情绪分类链迁移到角色声音资产链。页面提供角色卡片摘要、声音设置首屏输入和最终 VoiceDesign 指令摘要三处可见反馈；前端迁移采用可取消草稿，后端保留同一门禁。QwenEmotion 的异常模型输出不再中断候选生成，并保留可追查的原始异常。

生产镜像、7864 容器、真实工程保存与刷新、桌面及手机浏览器布局均已验收。现有旁白稳定音色未自动重做，因此“成都口音”对实际音色的听感验证仍需用户决定是否让整名旁白全篇使用该口音后，再生成新的角色音色候选。
