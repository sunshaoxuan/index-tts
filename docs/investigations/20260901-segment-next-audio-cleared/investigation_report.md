# 分句生成后相邻音频清空调查

## 问题

当前工程插入分句后，旧完整交付的片断序号发生整体偏移。重新生成当前分句时，`latest-render` 按旧序号覆盖片断，导致相邻已有音频从页面状态中消失。

## 根因

服务端原逻辑用新 draft 的 `order` 删除完整交付 manifest 中相同 `order` 的片断。前端实际使用原文和合成文本识别片断，因此服务端序号覆盖与前端身份契约不一致。

## 修复契约

完整交付片断与新生成片断共同进入候选池，按照当前工程顺序以原文和合成文本进行一对一匹配。当前序号完全一致的候选优先，新生成候选在同序号内优先，每个候选最多消费一次，返回序号统一改写为当前工程序号。

该规则覆盖插入、删除、拆分、合并造成的序号漂移，也覆盖重复文本不能共享同一音频的情况。
