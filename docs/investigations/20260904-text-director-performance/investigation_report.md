# AI 文本导演性能调查与优化报告

## 用户目标

AI 文本导演应先拆分任务，再按原文顺序逐段解析。本地大模型不得长期停留在首块和 0%，失败块应及时缩小并继续处理。

## 根因

2026-09-04 的真实任务 `4caad3449bee4d82b0495b7fca7d02ef` 使用 `qwen3:14b` 分析 1581 字符原文。任务输入配置为 1400 字符初始块和 600 秒单请求超时。

Ollama 日志显示体裁判断先用 4096 上下文，后续注册与分句使用 8192 上下文。同一个 14B 模型因此建立了两次 runner，加载阶段分别约为 237.61 秒和 206.35 秒。进入正文后，一个请求在 600 秒返回 500；后续一个自适应子块又运行约 9 分钟。原实现只在大块失败后拆分，并允许相同尺寸校验重试。首块状态使用 `index / total`，覆盖了前序连接进度并回到 0%。

## 实施结果

1. Product Studio 在正文分析前发送 8192 上下文空请求预加载 Ollama，并保持模型驻留。
2. 体裁判断、全文注册与逐块导演统一使用 8192 上下文，避免参数切换引发 runner 重建。
3. 本地全文先按自然边界预拆分，实际块长不超过 700 字符，再按原文顺序逐块解析。
4. 冷启动窗口保留 600 秒。驻留模型的单块窗口限制为 120 秒，Product Studio 每块只执行一次同尺寸尝试，失败后立即细分或进入无损安全分段。
5. 进度先报告拆分总数，首块从正进度开始；全文分析、人物校验与补充路由映射为单调递增的产品阶段。

## 边界

模型首次冷加载仍受本机磁盘、显存和 Ollama runner 初始化影响。600 秒只用于独立预热阶段。真实部署后的同稿性能、浏览器进度、Console 与截图在最终验收中记录。
