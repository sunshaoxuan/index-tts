# AI 文本导演性能调查与优化报告

## 用户目标

AI 文本导演应先拆分任务，再按原文顺序逐段解析。本地大模型不得长期停留在首块和 0%，失败块应及时缩小并继续处理。

## 根因

2026-09-04 的真实任务 `4caad3449bee4d82b0495b7fca7d02ef` 使用 `qwen3:14b` 分析 1581 字符原文。任务输入配置为 1400 字符初始块和 600 秒单请求超时。

Ollama 日志显示体裁判断先用 4096 上下文，后续注册与分句使用 8192 上下文。同一个 14B 模型因此建立了两次 runner，加载阶段分别约为 237.61 秒和 206.35 秒。进入正文后，一个请求在 600 秒返回 500；后续一个自适应子块又运行约 9 分钟。原实现只在大块失败后拆分，并允许相同尺寸校验重试。首块状态使用 `index / total`，覆盖了前序连接进度并回到 0%。

## 实施结果

1. Product Studio 在正文分析前发送 8192 上下文空请求预加载 Ollama，并保持模型驻留。
2. 体裁判断、全文注册与逐块导演统一使用 8192 上下文，避免参数切换引发 runner 重建。
3. 本地全文先按自然边界预拆分，实际块长不超过 400 字符，再按原文顺序逐块解析。真实首轮复测的 700 字符级块连续触发覆盖细分，产生 7 次正文请求；400 字符上限用于减少失败请求和动态二次拆分。
4. 冷启动窗口保留 600 秒。驻留模型的单块窗口限制为 120 秒，Product Studio 每块只执行一次同尺寸尝试，失败后立即细分或进入无损安全分段。
5. 进度先报告拆分总数，首块从正进度开始；动态细分增加总块数时保留已报告的最高逐段进度；全文分析、人物校验与补充路由映射为单调递增的产品阶段。

## 《成都粉子》空结果回归

新镜像任务 `7266224af1914c17ad44ec93c2517a63` 已在约 8 分钟内完成前序分析，随后在第 2 轮人物校验终止。模型对 `role_002` 刘至诚和 `role_003` 欣雨连续声明 `corrected`，问题只指出原文没有明示当前年龄并要求修正 `age_evidence` 与 `age_basis`，返回字段仍与当前推断字段相同。严格的字段变化门禁三次拒绝后使原子工程更新整体回滚，实际工程保持 0 个角色与 0 个分句。

首轮修复后的真实任务 `f505a93eb36241b990fa3b96fc7196ee` 仍因 `role_002` 失败，表明该人物继续使用 `current_explicit`。第二轮修复扩展窄范围确定性协调。当前字段已经使用 `current_inference` 或 `linked_inference`、年龄证据非空，且 issue 只重复指出年龄未明示时，人物改判为通过并清空重复 issue。当前文章的历史时间点年龄被错误标成 `current_explicit` 时，协调器降级为 `current_inference`，移除证据中的明示措辞并追加推断说明。缺少证据、指定了不同年龄目标或涉及其他人物字段的问题继续由原门禁拒绝。回归测试使用本次任务的两条真实 issue，并覆盖明示类型的确定性降级。

部署第二轮修复后，`ollama ps` 显示任务结束时 `qwen3:14b` 驻留上下文为 12288。代码复核确认人物校验请求仍单独指定 12288，下一任务预热会切回 8192 并再次重建 runner。导演补充语义路由另有 4096 上下文和主动卸载配置。最终修复把人物校验与导演补充路由同步为 8192 和 30 分钟驻留，并用人物校验及路由测试断言结构化请求参数，保证体裁判断、全文注册、正文分块、人物校验和补充路由复用同一 runner 配置。

## 边界

模型首次冷加载仍受本机磁盘、显存和 Ollama runner 初始化影响。600 秒只用于独立预热阶段。修复后的真实同稿生成、持久化覆盖、浏览器进度、Console 与截图在最终验收中记录。
